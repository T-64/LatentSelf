# LatentSelf 全流程

> 2026-11-27 已确认（A1–A6）。可直接实现的分阶段 spec：P1-SPEC.md、P2-SPEC.md、P3-SPEC.md、P4-SPEC.md。本文件是 DESIGN.md 的「流程版」：从原始数据到每一种产出，每一步的输入、输出、模型和存储都写清楚。DESIGN.md §4.2 的算法部分以本文件为准。

## 0. 两个空间

整个系统建立在两种互补的表示上：

| | **检索空间**（dense） | **可解释空间**（sparse） |
|---|---|---|
| 是什么 | embedding 模型给每段文字（和图片）算出的一个向量 | 一个大语言模型「读」这段文字时，内部激活经稀疏自编码器（SAE）拆出的上万个稀疏特征 |
| 擅长 | 找「意思相近」的东西：搜索、近邻、话题聚类、推荐打分 | 回答「这段话里有什么成分」：每个特征是一个概念方向，可以统计、比较、追踪、解释，还能定位到具体是哪几个字触发的 |
| 不擅长 | 向量的每一维没有含义，说不清「为什么相似」 | 不是为相似度优化的，直接拿来做检索效果一般 |
| 模型 | Qwen3-VL-Embedding-8B（主候选）/ Qwen3-Embedding-8B（对照） | 读者模型 Qwen3.5-9B-Base + 官方 Qwen-Scope SAE（W64K，覆盖全部层） |
| 用在 | P1 搜索、P3 话题、P4 推荐候选 | P3 画像和可解释性研究、P4 推荐理由、P5 可视化 |

最初的设想是「高维里有一些说不清、但能指向别的东西的特征」，这正好对应可解释空间。检索空间负责把东西找出来，可解释空间负责说明找到的是什么。

### 为什么这样选模型（2026-11 调研）

- **语言**：提问里中文占 93.5%，英文 5.1%，德语只有 0.6%（按字符启发式统计）。所以选型以中文效果为准，不考虑主打欧洲语言的模型（harrier 已从候选中移除）。
- **检索空间**：
  - Qwen3-VL-Embedding-8B：文字和图片在同一个空间。
  - Qwen3-Embedding-8B：中文证据最充分，C-MTEB 73.84。
  - 两者都来自 Qwen 系列，中文训练数据充足。在评测集上比较后再定，默认用 VL（见 P1-SPEC §5.0）。
- **可解释空间**：Anthropic 风格的可解释性研究，需要「一个模型 + 训练好的 SAE」。Qwen 在 2026-05 发布了官方的 [Qwen-Scope](https://huggingface.co/collections/Qwen/qwen-scope)：14 组残差流 TopK SAE，覆盖 Qwen3 和 Qwen3.5 的 7 个模型、每一层；Qwen 的论文里展示了中文相关的特征。在 48GB 显存上能用 bf16 跑的组合里，最新的是 **Qwen3.5-9B-Base + SAE-Res-Qwen3.5-9B-Base-W64K**（6.5 万个特征 × 32 层）。
  - 另一个选项 Qwen3.5-27B（SAE 是在 instruct 版上训练的）用 bf16 约需 54GB，放不进显存；量化后激活分布会偏移，SAE 就不准了。
  - 方法上参考 [Jiang, Nanda et al. 2025, *Interpretable Embeddings with Sparse Autoencoders*](https://arxiv.org/abs/2512.10092)：对每个 token 编码 SAE，再在 token 维度上取 max，得到文档级的特征向量；用它来做数据集对比（diff）、相关性分析、聚类和按概念检索。他们的结论是，这类分析比用 LLM 直接读全文便宜 2–8 倍，而且能发现 dense embedding 发现不了的结构。
- **LLM / 视觉**：Qwen3.8-27B，Unsloth GGUF（服务器上已有），负责图片描述、查询扩展、相关性判断、特征起名、摘要。
- **所有模型都在服务器上运行**（RTX 4090 D 48GB，因为时差大多空闲）。Mac 不下载、不运行模型。

## 1. 流程总览

```
L0 原始快照 ──► L1 统一模型 ──► L2 补全 ──► L3 分析单元
                                                │
                     ┌──────────────────────────┴───────────────────────┐
                     ▼                                                  ▼
              L4a 检索空间（dense）                              L4b 可解释空间（SAE）
                     │                                                  │
                     ▼                                                  ▼
              L5a 话题（Leiden）                         L5b 特征说明（auto-interp）+ 基准频率
                     └──────────────────────────┬───────────────────────┘
                                                ▼
                              L6 分析：统计 · 话题时间线 · 特征看板 · 数据集对比 · 相关性 · 画像
                                                ▼
                              L7 应用：搜索 · 推荐 · 写作（MCP）· 可视化
```

每一层都是**增量**的：新快照进来后，只重算新增或变化的单元。每一层的产出都写进 `ls.db`（只有向量这类大块数据可以另存为 `.npy` 文件，表里记下路径）。

## 2. 各层详细说明

### L0 原始快照（已有）
`~/data/raw/gemini/<YYYY-MM-DD>/{MyActivity.json, attachments/}`，只读。

### L1 统一模型（P0 已完成）
`turn / conversation / turn_conv / answer / attachment / canvas / signal`，加上 FTS。

### L2 补全（P1）
- 图片和 Live 帧：生成描述、OCR、标签、内容类型（Qwen3.8-27B 视觉）。
- PDF 和 DOCX：抽取文本。
- Gemini 生成的图片标成 `origin='generated'`。这类图片**不参与画像**，只用于搜索。

### L3 分析单元（P1 定义，各层共用）

| 单元 | 内容 | 用途 |
|---|---|---|
| `turn.doc` | 提问 + 回答前 500 字 + 附件描述 | 检索 |
| `turn.self` | **只有提问**和附件描述（我说的话、我拍的东西） | 画像、可解释空间。理由是回答是 Gemini 的话，混进来会把它的口吻当成我的特征 |
| `turn.answer` | 回答全文（draft 0） | 可选：单独分析「AI 给了我什么」 |
| `conversation` | 由各轮聚合：dense 用均值，SAE 用 max | 话题、对话级统计 |
| `episode` | 跨对话、按时间切分的使用段（相邻两轮间隔超过 30 分钟就切开） | 一天里的使用节奏、深夜段分析 |
| `day / week / month` | 时间桶 | 时间序列、对比 |

超长提问（p99 约 5,000 字，最长约 19.5 万字，基本是粘贴进来的文档）在 L4b 里按 1,024 token 切块，取各块 max 的再 max。另外标记 `is_paste=1`，画像时降低它的权重：粘贴的是别人的文字，不是我写的。是否算粘贴的判定规则由实现者给出，并在样本上核对。

### L4a 检索空间（P1）
- 向量：`turn.doc`、`turn.self`、图片，存在 `embedding(item_kind, item_id, model)` 表里。
- 对话向量：由各轮向量按长度加权求均值，按需计算并缓存。
- 查询时也走服务器上常驻的 embedding 服务。

### L4b 可解释空间（P3）

1. **读者模型候选**（都配各自的 Qwen-Scope `layer{n}.sae.pt`，在服务器上运行）：
   - **Qwen3.5-9B-Base** + W64K（bf16，约 18GB，可以直接放进显存）：默认候选。
   - **Qwen3.5-27B** + W80K（SAE 训练在 instruct 版上；bf16 约 54GB，超出 48GB 显存）：试两种跑法：
     - (a) bf16 + 部分层卸载到 CPU（accelerate `device_map`），结果准确但慢；
     - (b) 8-bit 量化，速度快，但激活可能偏移。

     两种跑法都要测重构误差。如果 (b) 的 FVU 比 (a) 差超过 10%（相对值），就视为量化不可用。
2. **选模型和选层**（先用小样本做实验）：在同一批 2,000 个 `turn.self` 上，每个候选模型取中间若干层（9B 例如第 8、12、16、20、24 层；27B 按相对深度取对应的层），分别统计：
   - 重构质量：FVU，以及把重构结果代回模型后语言模型损失增加多少；
   - 死特征比例；
   - 让 LLM 给每层随机 50 个特征起名，再看名字能不能在没见过的样本上预测激活（检测分数）。

   此外，两个模型都要记录处理 2,000 个样本的耗时，并据此推算全量（约 300 万 token）的耗时。

   决策规则：
   - 默认用 9B。
   - 27B 只有同时满足两个条件才用它：①它的最佳层在检测分数上比 9B 的最佳层**高出 ≥ 5 个百分点**，且 FVU 不比 9B 差；②全量计算能在 24 小时内跑完（服务器大多空闲，跑得慢可以接受）。

   选出模型和 1–2 个主层，结果写进 `docs/P3-LAYER-EVAL.md`（只放汇总数字）。
3. **编码**：对每个 token 编码 SAE，**丢掉第 0 个 token**（Qwen 论文提到它的激活是异常值）。注意模型卡的示例代码里 TopK 之前没有 ReLU，实现时要和论文核对：负值应该截掉。
4. **池化**：对每个单元在 token 维度上取 max，得到 `act[f]`；同时记下取到最大值的 token 位置，展示时用来高亮。
5. **长度偏差**：max 池化会让长文本点亮更多特征。所以除了原始激活，还要存一份**按长度桶标准化**的版本（同一长度区间内做 z-score），供统计使用。
6. **存储**：每个单元只存非零的前 128 个特征 `(unit, layer, feature, act, argmax_pos)`；原始的逐 token 激活不存，展示时现算。
7. **开销估算**：1.5 万个单元，平均约 200 token，合计约 300 万 token。用 9B bf16 做一次前向，同时挂多层 SAE，预计不到 1 小时。

### L5a 话题（P3）
- 对话级向量 → 互为近邻的 kNN 图（k≈15） → Leiden，扫描多个分辨率，得到层级话题树。
- 话题名：由 LLM 根据话题内的代表对话起一个短名字。
- 另外做一份**特征聚类**：把 SAE 向量二值化，用 Jaccard 相似度做谱聚类，和 dense 话题对照着看。论文的发现是：dense 按「主题」聚，SAE 按「风格或思维方式」聚。
- **同一个爱好是否反复出现**：对每个话题统计按天的活跃序列；间隔 14 天以上再次出现，记为一次「复发」。输出复发次数、首次和最近出现时间、活跃的跨度。

### L5b 特征说明与基准频率（P3）

- **只解释「在我的数据里活跃」的特征**：6.5 万个特征里，预计真正在我的数据里出现的只有几千个。
- **自动起名**（auto-interp，方法参考 Paulo et al.）：
  1. 每个特征取 10 个最强激活片段（带高亮）、10 个随机激活片段、10 个不激活的片段，交给本地 LLM 写一个短名字和一句说明。
  2. 再做检测打分：把名字给 LLM，让它在新样本里预测哪些会激活。打分低于阈值的特征标为「难以命名」。**这些不丢弃**，它们正是「说不清，但存在」的那一类。
  3. 名字只作为辅助，界面上始终以样本为准。
- **基准频率**：要回答「哪些特征是我特有的」，需要一个参照。在服务器上用公开的中文对话语料（例如 WildChat 或 LMSYS-Chat-1M 的中文子集，抽 1–2 万条用户提问）跑同一套编码，得到每个特征的基准激活频率。

  **我的特有程度** = 我的激活频率相对基准的富集程度（log-odds，加上平滑和显著性检验）。

### L6 分析（P3，产出都是可复现的报告）

| 分析 | 做法 | 回答的问题 |
|---|---|---|
| 基础统计 | 按小时、星期、月份统计提问数；长度分布；语言比例；附件类型；对话轮数分布；按 episode 统计时长 | 我什么时候用、怎么用 |
| 话题时间线 | L5a 的话题 × 时间，加上复发统计 | 哪些兴趣是长期的，哪些是一阵子的 |
| 特征看板 | 每个特征一页：名字和检测分数、最强激活样本（逐 token 高亮）、激活直方图、按周的时间序列、共现最多的特征、decoder 方向余弦最近的特征 | 这个特征是什么、什么时候出现 |
| 特有特征 | L5b 的富集排名 | 我和一般人比，有什么不同 |
| 数据集对比 | 对任意两组单元比较特征频率（加显著性检验）：例如时间段 A 对 B、深夜对白天、带图对纯文字、长对话对短对话 | 我在不同时期、不同状态下有什么变化 |
| 相关性 | 特征两两之间的 NPMI，筛出共现强、但名字语义不相近的组合 | 意想不到的关联 |
| 画像 | 特有特征 × 时间衰减（半衰期可调） × 显式信号，每个特征附上证据轮次 | 现在的我由哪些方向构成 |
| 搜索质量 | P1 评测 | 搜得准不准 |

所有分析都写成函数，CLI 输出 Markdown 或 JSON 报告，放在 `$LATENTSELF_OUT/analysis/<日期>/`。报告里出现的每个数字都能回溯到具体的单元。

### L7 应用
- **搜索**（P1）：见 P1-SPEC。P3 之后加一个「按特征搜索」：给出一个特征，列出所有激活了它的轮次。
- **写作**（P2）：月度摘要和事实层，加上 MCP 工具（search / show / timeline / facts / features / topics / stats），由 Claude Code 或本地 agent 调用。
- **推荐**（P4）：
  - 候选：电影（之后扩展到书、音乐）的元数据文本，用同一套模型算出 dense 向量和 SAE 特征。
  - 打分：`α·dense 相似度（与画像中心以及最近若干轮）+ β·Σ 画像特征权重 × 候选特征激活`，再加多样性约束（MMR），并排除看过的。
  - 理由：列出候选点亮了哪几个画像特征，每个特征附上我的 2 条原话。
  - α、β 在留出数据上调：把我在对话里提到过的电影当作正样本做回测。
- **可视化**（P5）：等 L6 的报告出来后再选。候选：特征时间河流图、日历热力图、话题层级图、对话级二维地图（只用来导航，所有结论都在高维空间里计算）、单个特征的 token 高亮看板。
