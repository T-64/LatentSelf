## 1. 残差流（residual stream）

Transformer 由一层层的块堆起来。每个 token 在每一层都有一个向量 `x ∈ ℝ^d`（Qwen3.5-9B 的 d = 4096），每一层的注意力和 MLP 只是往这个向量上**加**一点东西：

```
x_{l+1} = x_l + Attn_l(x_l) + MLP_l(x_l)
```

这条一路累加下去的向量通道，就叫残差流。它是模型的「工作记忆」：前面各层读到的、推断出的东西，都以方向的形式叠加在里面。Qwen-Scope 的 SAE 训练的就是每一层的残差流（`model.model.layers[n]` 的输出）。

**层的直觉**：浅层更接近字面（词形、语言、格式），中层更接近语义和概念，深层越来越偏向「下一个 token 要输出什么」。可解释性研究通常在中间层取特征。所以选层实验取的是 9B 的第 8–24 层（共 32 层），27B 的第 16–48 层（共 64 层）。

## 2. 叠加（superposition）：为什么不能直接看维度

模型要表示的概念远远多于 4096 个，所以它把很多概念**叠加**在同一组维度里：每个概念是一个方向，方向之间几乎正交，但不严格正交。后果是，单看某一维，它会同时响应好几个毫不相干的概念（多义性，polysemanticity）。

稀疏自编码器的假设是：**每个 token 实际上只用到少数几个概念**。如果学到一组足够多的方向（字典），让每个 token 的向量都能写成其中少数几个方向的加权和，那么每个方向就更可能只对应一个概念（单义性，monosemanticity）。

## 3. SAE 的结构

```
编码：pre = x·W_encᵀ + b_enc          W_enc: (m × d)，m 是特征数，例如 65,536
稀疏：z = TopK(pre, k)                 只保留最大的 k 个，其余置 0（Qwen-Scope：k = 50 或 100）
解码：x̂ = z·W_decᵀ + b_dec             W_dec: (d × m)，每一列是一个特征方向
```

- **特征** = W_dec 的一列（方向），加上 W_enc 的一行（探测器）。`z_i` 是第 i 个特征在这个 token 上的**激活强度**。
- **稀疏化的几种方式**：
  - ReLU 加 L1 惩罚：早期做法，激活数量不固定。
  - **TopK**：每个 token 固定激活 k 个特征，直接控制稀疏度。OpenAI 2024 年提出，Qwen-Scope 用的就是这种。
  - JumpReLU：每个特征一个可学习的阈值，Gemma Scope 和 Qwen3-Instruct SAE 用的是这种。
- **L0** = 平均每个 token 有多少个非零特征。TopK SAE 的 L0 就是 k。
- **宽度**（特征数 m）：越宽，概念拆得越细。但也越容易出现「特征分裂」（一个概念拆成好几个），以及「死特征」（从来不激活）。

## 4. 怎么评价一个 SAE

| 指标 | 定义 | 好的方向 | 项目里的数字 |
|---|---|---|---|
| **FVU**（未解释方差比例） | Σ‖x − x̂‖² ÷ Σ‖x − x̄‖² | 越低越好；1 相当于「直接猜平均值」 | 9B 真实样本 0.38–0.45（模型卡写法） |
| **ΔCE**（下游损失增量） | 把这一层的残差替换成 x̂，下一个 token 的交叉熵增加多少 | 越低越好；它衡量的是「重构误差有没有伤到模型的功能」 | 合成冒烟 0.17–0.78，真实样本待测 |
| **死特征比例** | 在一批数据里从来不激活的特征占比 | 越低越好；不过在只有 1.5 万条的个人语料上，死特征多是正常的 | 待测 |
| **可解释性** | 给特征起个名字，再看这个名字能不能预测新样本上的激活（§7） | 越高越好 | 待测 |

FVU 低不等于好解释，好解释也不等于 FVU 低，所以选型时要同时看。

## 5. 编码约定的坑：推理必须和训练一致（实验 E1）

不少论文里 TopK SAE 的写法是先「中心化」：`pre = ReLU((x − b_dec)·W_encᵀ + b_enc)`。Qwen-Scope 模型卡的示例代码没有这一步。

我们在两个模型、五层上做了对比，结果一边倒：模型卡写法的 FVU 是 0.38–0.53；中心化写法是 0.73–5.94，多数层超过 1，也就是比直接猜平均值还差。

**为什么**（推测）：训练时如果没有减 b_dec，编码器的偏置 b_enc 就已经把平移「吸收」掉了。推理时再减一次，相当于给每个特征的预激活都加了一个固定偏移 `−W_enc·b_dec`。这样一来，进入 TopK 的就不再是正确的那 50 个特征，重构就会崩。

**教训**：SAE 的编码函数是它的一部分，必须和训练时的代码**逐字一致**。拿到别人的 SAE，第一件事是在自己的数据上算一下 FVU：如果大于 0.8 左右，十有八九是编码约定搞错了。

## 6. 从 token 到文档

SAE 是对每个 token 单独编码的。要得到「一段话」的特征，需要池化：

- **max 池化**（项目采用，参考 Jiang & Nanda 2025）：每个特征取这段话所有 token 上的最大激活，同时记下最大值出现在哪个 token，用来高亮。直觉是：只要有一处明确表达了某个概念，这段话就「含有」这个概念。
- **第 0 个 token 要排除**：模型往往把序列开头的 token 当作「注意力的停放处」，它的残差范数会大得异常（massive activations）。不排除的话，一些特征会在每段话的开头都被点亮。
- **长文切块**：超过 1,024 token 就切块，相邻块重叠 64 token，各块分别取 max，再在块之间取 max。实验 E3 验证了峰值位置能复现。
- **长度偏差**：max 池化天然偏向长文本，因为 token 越多，碰上某个特征的机会越多。所以统计时用的是**按长度分桶后再标准化**的 `act_z`。

## 7. 给特征起名（auto-interp）

做法参考 Paulo et al. 2024：

1. 把某个特征最强的 10 个激活片段（被点亮的字用 `«»` 标出）、10 个随机的激活片段、10 个不激活的片段，一起交给 LLM，让它写一个短名字。
2. **检测打分**：另取 10 个激活片段和 10 个不激活片段，打乱顺序，让 LLM 只根据名字判断每个片段会不会激活。平衡准确率就是 detect_score；0.5 相当于瞎猜。
3. 分数低的特征**不丢弃**，标为「难以命名」。它们可能是真正的复合概念，也可能是 SAE 的瑕疵，需要人去看样本判断。

需要知道的现象：
- **特征吸收（absorption）**：一个更具体的特征把一般特征的一部分激活「吃掉」。比如「首都」特征在「巴黎」上不激活，因为「巴黎」有自己的特征。所以名字往往比特征实际覆盖的范围宽。
- **特征分裂**：SAE 越宽，同一个概念越容易拆成好几个更细的特征。

## 8. 用特征做统计

有了每段话的稀疏特征向量，就能做传统的「计数统计」：

- **富集（我特有的）**：对每个特征，比较它在我的数据里和在基准语料（WildChat 中文提问）里的激活频率。
  - log-odds 差（加 0.5 平滑）：`log(p₁/(1−p₁)) − log(p₂/(1−p₂))`。
  - 两比例 z 检验：给出显著程度。
- **多重比较**：同时检验上万个特征，必然会有一批「碰巧显著」的。用 Benjamini–Hochberg 方法控制错误发现率（FDR），给出 q 值。
- **对比（diff）**：同样的检验，拿来比较我自己的两组数据，例如两个时期、深夜和白天。
- **共现（NPMI）**：`log(p(a,b) / (p(a)·p(b))) ÷ (−log p(a,b))`，取值在 −1 到 1 之间。接近 1 表示两个特征总是一起出现。如果两个特征语义不相近，却总是一起出现，那就是意外的关联。
- **聚类**：把特征向量二值化，用 Jaccard 相似度做谱聚类。按 Jiang & Nanda 的发现，这样聚出来的偏「风格和思维方式」，而 dense embedding 聚出来的偏「话题」。

## 9. 量化与卸载（实验 E2）

- **bf16**：16 位浮点，是 SAE 训练时用的精度。27B × 2 字节 ≈ 54GB，超出 48GB 显存。
- **CPU 卸载**：放不下的层放到内存里，算到哪一层，就临时搬到 GPU 上。结果和 bf16 完全一样，但很慢：10 条样本 21.7 秒。
- **int8（LLM.int8）**：把权重量化成 8 位整数，对离群维度保留高精度，显存减半。风险是激活会稍有偏移，SAE 的重构可能变差。
- **实测**：int8 的 FVU 只比卸载高 0.3%–1.2%，速度却快约 2.5 倍（8.6 秒）。结论：做 SAE 分析时，int8 可以接受。

## 10. 检索空间：embedding

- **双塔（bi-encoder）**：查询和文档各自独立编码成向量，用余弦相似度比较。文档向量可以提前算好存起来，所以检索很快。Qwen3-Embedding 和 Qwen3-VL-Embedding 都属于这一类。
- **指令前缀**：Qwen3-Embedding 要求查询前面加上 `Instruct: <任务>\nQuery: ...`，文档不加。模型卡说，去掉指令，检索效果会差 1–5%。
- **多模态 embedding**：Qwen3-VL-Embedding 把图片和文字映射到同一个空间，所以可以用文字直接搜图片。
- **MRL（Matryoshka）**：训练时让向量的前 n 维单独拿出来也能用，所以可以把向量截短，省空间。
- **归一化**：向量先做 L2 归一化，余弦相似度就等于点积。项目里用 float16 存储，归一化后的误差 < 0.001。
- 实验 E4：两个模型的前 300 个结果平均只重合约 24%。模型之间的差异很大，只能靠标注来判断谁更好。

## 11. Reranker 与混合检索

- **交叉编码器（cross-encoder / reranker）**：把查询和文档拼在一起，让模型直接输出一个相关性分数。比双塔准，但每对都要单独算一遍，只能用在少量候选上做「第二道」筛选。
- **混合检索**：关键词召回和向量召回取并集。关键词擅长专有名词和精确字面，向量擅长同义改写。
- **FTS5 的 trigram 分词**：把文本切成三个字一组建索引，中文不需要分词器就能做子串匹配；少于 3 个字的查询退回到逐行扫描。
- **查询扩展**：让 LLM 把查询词扩展成同义词和外语说法，提高召回率。但它很慢（实验 E5，约 5 秒），所以只在 strict 模式里用。

## 12. 怎么评测「找全了没有」（实验 E8）

- **召回率** = 找到的相关条目 ÷ 全部相关条目；**精确率** = 找到的相关条目 ÷ 找到的全部条目。
- 难点在于：「全部相关条目」是未知的，不可能人工读完 1.5 万轮对话。
- **候选池法（pooling）**：信息检索评测（TREC）的老办法。把多个系统、多种召回方式的结果合在一起作为候选池，假设池外基本没有相关条目，只在池内标注。
- **分层抽样**：池还是太大（我们的有 3,469 条），那就按「有几路命中、strict 判断的结果」分层，每层只抽少量样本来标注。
- **Horvitz–Thompson 估计**：每条样本的权重 = 该层池大小 ÷ 该层抽样数，然后用加权后的计数估计召回率和精确率。这样即使各层的抽样比例不同，估计也是无偏的。
- **bootstrap 置信区间**：在每层内部有放回地重抽 1,000 次，取估计值的 2.5% 和 97.5% 分位数，看结论是否稳定。
- **不要循环论证**：被测系统自己的判断（例如 strict 模式的结果）只能用来分层，不能当作标准答案。

## 13. 话题：kNN 图 + Leiden

- **K-means 的问题**：要预先指定簇的数量；默认簇是球形、大小相近；每个点都必须归到某个簇。个人语料的话题大小可以差几百倍，形状也不规则。
- **kNN 图**：每个对话连向和它最相似的 k 个对话，只保留「互为近邻」的边，以减少噪声。
- **Leiden**：一种社区发现算法，优化的是模块度（或 CPM）这类目标，只依赖局部的连接关系。分辨率参数控制社区的粗细：扫描多个分辨率，就得到一棵层级话题树。它比 Louvain 多了一步保证社区内部连通的细化。
- **复发**：一个话题的活跃日期之间如果间隔超过 14 天，就算一次复发。用来区分「长期兴趣」和「一阵子的兴趣」。

## 14. 动手练习

用仓库里的 NumPy 参考实现 `latentself/interp/sae_io.py: topk_sae` 完成：

1. 随机生成一个小 SAE（d = 16，m = 64，k = 4），用 `card` 写法编码一批随机向量，算 FVU。
2. 把 b_dec 设成越来越大的偏移（0、1、5），分别用 `card` 和 `centered` 两种写法编码同一批向量，比较两种写法选出的 top-k 特征集合有多少重合。你会看到：偏移越大，重合越少。这就是实验 E1 中重构崩坏的机制。随机 SAE 本身没有「正确」的写法，所以这里不比 FVU，只看特征集合的变化。
3. 把 k 从 1 扫到 32，画出「k 和 FVU」的关系曲线，体会稀疏度和重构之间的权衡。
4. 写一个 `Pool`，喂入两段 token 激活，验证 max 池化和第 0 个 token 的排除。
