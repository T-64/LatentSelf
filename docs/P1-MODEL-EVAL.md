# P1 检索模型评测

2026-11-27。评测包含 9 条私有查询，其中 2 条用于寻找目标照片。两个候选模型使用同一批轮次。模型选型和检索验收仍在进行。

对照轮次来自扩展关键词命中以及带图片的轮次。检查压缩包目录后补入了 17 个记录为普通提问的 Live 帧包。用唯一匹配的导出文件名修复了 37 张图片和 1 份 PDF 的路径。照片相关性和目标文件由人工核对。

多模态模型的 8,480 条向量均为 4,096 维，float16 存储后的 L2 范数与 1 的差都小于 0.001。按当前提问、回答和附件描述重建了全部 5,518 份文本输入。另从本地原件重新处理 2,962 份附件，其中有 2,881 份用户图片、59 份生成图片、22 份 Live 帧包。逐条对照写入索引时保存的输入哈希，文本和附件均为 0 处不一致。

纯文本模型的 5,518 条向量通过了相同的维度、范数和输入校验。两个模型的轮次 ID 和文本哈希逐条相同。在 7 条文本查询中，两个模型各自召回的前 300 个轮次平均重合 71.14 个，最少 26 个，最多 155 个。重合数描述候选差异，相关性由下文的评测标签判定。

## 服务实测

- Qwen3-VL-Embedding-8B 的文档、查询、单图和三帧 Live 请求都返回了 4,096 维向量。归一化后写入 SQLite，每条向量占 8,192 字节。
- 在同一块 GPU 上同时加载视觉语言模型和多模态向量服务时，向量服务分别在 0.36 和 0.38 两种显存分配比例下未能分配 KV 缓存。单独启动向量服务并设为 0.80 后，服务报告有 21.78 GiB 可用于 KV 缓存。
- 在批量建索引同时运行一次 fast 查询，向量请求耗时 8.31 秒，整次检索耗时 8.51 秒。这次使用部分索引。最终延迟将使用完整索引，并记录测试时的服务负载。
- 单独加载 Qwen3-VL-Reranker-8B 后，对一组包含 2 份文档的合成请求实测。相关文档得分 0.10860，无关文档得分 0.00098，顺序符合预期。strict 模式的上下阈值将用私有评测集标定。
- 搜索时只需编码文字查询。VL 服务关闭视觉输入并固定 1.5 GiB KV 缓存后，和 27B LLM 同时就绪，实测共用显存 48,144 MiB。9 个查询向量与完整 VL 服务的对应向量最低余弦相似度为 0.99999988，往返耗时中位数 2.78 秒，范围 1.11–6.08 秒。
- 在 LLM 同时处理候选标注、使用对照索引的负载下，实际文字搜图和普通文字检索各返回 200 个候选，分别耗时 4.01 秒和 7.28 秒，超过 3 秒目标。同一轮 strict 冒烟处理 9 个候选，返回 3 个，含排队耗时 256.66 秒。超过 180 秒后卸载了已用完的查询实例，保留 LLM 完成判断。单独运行时的最终时延仍待全量测量。

## 选型与验收

模型比较使用每条查询的召回率、精确率和耗时。纯文本模型在文本查询上的平均召回率比多模态模型高至少 3 个百分点时启用双模型检索。strict 策略比较逐批 LLM 判断和 reranker 初筛后判断边界候选的结果。

按评测约定，文本查询只有一路命中的候选交给人工判断，两路及以上命中的候选记为自动一致。数据库单独记录自动一致标签的来源，重建候选池时保留人工决定。照片查询逐项由本人核对目标文件。因此，后续指标使用的参考标签同时包含人工判断和多路召回共识。

目前尚未取得完整人工标签，两个候选模型的召回率差、strict 精确率以及目标照片的前五命中均待测。
